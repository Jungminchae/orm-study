# Quiz CLI Orchestrator

파이썬 퀴즈 CLI 마이그레이션 및 개발을 총괄하는 오케스트레이터 스킬입니다.
`cli-developer`, `quiz-maker`, `qa-tester` 서브에이전트를 활용하여 전체 라이프사이클을 관리합니다.

## 워크플로우

### Phase 0: 컨텍스트 확인
1. 기존 프로젝트 상태를 확인합니다. `pyproject.toml` 또는 `poetry.lock` 여부 확인.
2. 기존 작업물(`_workspace/` 내의 기획/설계 문서 또는 이전 단계 산출물)이 있는지 확인합니다.
3. 사용자가 전체 마이그레이션을 원하는지, 특정 부분(예: 퀴즈 추가)만 원하는지 파악합니다.

### Phase 1: 마이그레이션 및 CLI 기반 작업 (cli-developer)
- `invoke_subagent`를 통해 `cli-developer`를 호출합니다.
- **요청 내용**: "poetry에서 uv로 환경을 전환하고, Typer 기반으로 CLI 뼈대를 구축하라. 데이터 로더 및 라우팅 기초를 완성하라."
- 결과는 `_workspace/01_cli_foundation.md`에 요약하거나 코드베이스에 직접 반영합니다.

### Phase 2: 퀴즈 콘텐츠 생성 (quiz-maker)
- 기초 CLI 구조가 완성되면 `quiz-maker` 서브에이전트를 호출합니다.
- **요청 내용**: "파이썬 기초 챕터(예: 자료형, 제어문, 함수)에 대한 퀴즈 데이터를 JSON 또는 YAML 형태로 생성하라."
- 결과는 `_workspace/02_quiz_data_report.md`에 요약하고 데이터 파일은 지정된 경로에 저장합니다.

### Phase 3: 품질 보증 및 QA (qa-tester)
- 코딩과 콘텐츠가 준비되면 `qa-tester`를 호출합니다.
- **요청 내용**: "작성된 CLI를 실행하고 퀴즈 데이터를 불러와 테스트하라. 기능 오류 및 데이터 누락이 없는지 검증하라."
- 결과는 `_workspace/03_qa_report.md`에 기록됩니다.

### Phase 4: 수정 및 최종 보고
- QA 리포트에서 문제점이 발견되면, 오케스트레이터는 문제를 분류하여 다시 `cli-developer` 또는 `quiz-maker`에게 수정을 지시합니다.
- 모든 과정이 완료되면, 사용자에게 최종 완료 보고를 하고 CLI 실행 방법 등을 안내합니다.

## 에러 핸들링 원칙
- 특정 서브에이전트가 실패하거나 교착 상태에 빠지면, 해당 에이전트의 이전 단계 결과물로 롤백하거나 사용자에게 즉시 상황을 보고하고 피드백을 기다립니다.
